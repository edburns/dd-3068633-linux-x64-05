## Section 8: Observations and Recommendations

### What worked well

- Metadata consistency was strong: invocation values and the run manifest matched exactly, including the `off` lesson mode and successful exit code.
- Head-specific review IDs and SHAs prevented stale reviews from satisfying merge gates.
- The final gates checked current-head review, unresolved threads, workflows, base branch, mergeability, and refusal conditions before each merge.
- CCRA identified a real contract/type mismatch on [#8](https://github.com/edburns/dd-3068633-linux-x64-05/pull/8); the local CLI applied a focused two-file fix and added a precise overflow-boundary regression.
- Cleanup was verified after both merges, including topic branches and the temporary review worktree.

### What could improve

- The [#7](https://github.com/edburns/dd-3068633-linux-x64-05/pull/7) review overview mentioned premature overflow at `N=92` while declaring `Findings: None` and producing zero line comments. Because stage 40 treats top-level line comments as authoritative, that observation did not become a remediation cycle. CCRA summaries should avoid action-oriented language when no actionable finding is emitted, or the shepherd should explicitly classify summary-only risk text.
- Stage 30 tests for [#8](https://github.com/edburns/dd-3068633-linux-x64-05/pull/8) covered representative factorials only through `5!`, so they did not exercise the first value beyond `Int64`. Issue-derived tests should include numeric-boundary cases implied by the accepted input range and declared return type.
- The review overview continued to note that the helper always forwarded `-Operation fibonacci`, even after reporting no findings. Add an explicit omitted-`-Operation` CLI test to make backward-compatibility evidence unambiguous.
- Token values are redacted in the JSONL artifacts. If token comparison is required across control and treatment campaigns, export non-sensitive aggregate input/output token counts alongside `totalNanoAiu` in the run manifest.
- Persist per-round structured metrics (`reviewId`, head SHA, comment count, severity, resolution, elapsed time) in the stage outcome artifact. This would remove the need to reconstruct review convergence from Markdown transcripts.

Because lesson propagation was `off`, no campaign lesson updates were expected or made. The unchanged `campaign-lessons.md` is therefore consistent with the control-run configuration.
